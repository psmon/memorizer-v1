# ASKBOT Actor Model Upgrade

This project uses .NET 9.0 and consists of a full-stack (API, UI) architecture.
It enables search and vector search using PostgreSQL and graph traversal using Neo4j.

To improve the ASKBot feature, please perform the following improvements based on the ASIS issues and improvement guidelines.
Additional information required for the improvements is included, so please refer to the necessary parts and perform after fully understanding them.

## ASIS (Current State)
- While we have long-term memory using PostgreSQL that can be searched, this feature already exists.
- Currently, ASKBot can only provide single responses without considering previous and next conversations.
- There is no feature to continue conversations within the same session, so it cannot understand the context of conversations within a session.

## Improvement Guidelines
- ChatBotActor is created per user session and can temporarily store conversations per session.
- Up to 10 user conversations can be stored per session, and when exceeding 10, the oldest conversation is deleted.
  - Before deletion, important information from the conversation is analyzed and retained in short-term memory.
  - Short-term memory is maintained within 500 characters maximum, and is updated by comparing with new user conversation information.
  - When a response is completed, the most recent response is stored separately.
    - This is stored because there may be important content in the response that can be utilized in the next conversation.
    - The last response is not always referenced in every conversation.
- ChatBotActor generates responses using both short-term memory and long-term memory for conversation requests.
  - Short-term memory is used to understand the context of the conversation.
    - Hello, who are you? -> I'm ASKBot. Who are you? -> I'm a developer -> Oh, nice to meet you, developer
      - This way it's used to understand conversation context.
    - I have a question -> What's your question? -> I'm curious about AI development methodology -> Let me search my memory
      - This way it understands conversation context while performing memory searches.
  - Long-term memory is used to search for memories related to user requests. This is already implemented and can be utilized.
- Currently shows reasoning process. When no memory search is needed for simple responses, reasoning process is not displayed in UI.
  - The reasoning process feature works well, so it's only controlled in the UI. When search is needed, there are search results. Since events come, reasoning process can be displayed at this time.

## Project Location and Description
- Located under src/Memorizer/ subdirectory.
- src/Memorizer/Controllers - Contains API controllers.
- src/Memorizer/Services - Contains service logic including search logic.
- src/Memorizer/Services/ILlmService.cs - Can use LLM and embedding.
- src/Memorizer/Views - Contains UI-related view files.
- src/Memorizer/Actors - Contains actor models, refer to actor models when needed.
  - ChatBotActor.cs - Actor model that connects to users via SSE edge and processes conversation requests. Generates responses using search and decision actors.
  - SearchMemoryActor.cs - Actor model responsible for memory search.
  - DecisionActor.cs - Actor model that determines if searched memories are related to the request content.
  - MetadataEmbeddingActor.cs - Actor model responsible for metadata embedding. Processes metadata embedding asynchronously when registering memory. Vectorizes using embedding in this process.
  - GraphsyncActor.cs - Actor model that syncs PostgreSQL data to graph model using Neo4j.
- src/Memorizer.IntegrationTests - Contains integration test project.
- PageUrl: Has the following page URLs:
    - ui/blog
        - ViewMore: View content through popup button
    - ui/view/2b61629b-d5b4-41c2-8163-6670893df238: View content by ID
    - ui/askbot - Chatbot page
